# Retrieval evaluation

The datasets are versioned so benchmark history remains reproducible:

- `datasets/stack_ai_retrieval_v1.json`: frozen Sprint 1 baseline with 20
  legacy silver phrase cases. Do not edit this file when the corpus changes.
- `datasets/stack_ai_retrieval_v2.json`: active benchmark for the current
  documentation corpus with 20 project-aligned silver cases and 20 manually
  reviewed gold-qrel cases. The silver cases exercise ingestion, retrieval,
  citations, memory, providers, security, orchestration, and observability.

The runner uses `v2` by default. Pass `--dataset` explicitly to reproduce a
historical run.

The runner reports Hit Rate@K, Precision@K, Recall@K, MRR, nDCG@K, mean latency and p95 latency.

Run from the repository root after the collection has been indexed:

```bash
python -m backend.app.evaluation.run_retrieval --collection data_test --k 5
```

Compare dense-only, native BM25-only, and hybrid RRF using the same dataset:

```bash
python -m backend.app.evaluation.run_retrieval \
  --collection data_test \
  --k 5 \
  --compare-all \
  --summary-only
```

Silver cases check expected phrases and should be refreshed when the source
corpus changes. Gold cases use stable, manually reviewed qrels and can also
scope retrieval to selected documents:

```json
{
  "id": "rag-definition",
  "question": "RAG là gì?",
  "document_ids": ["00000000-0000-0000-0000-000000000001"],
  "relevant_chunk_ids": ["00000000-0000-0000-0000-000000000002"]
}
```

`relevant_chunk_ids` must be manually reviewed. Do not generate gold labels with the same retriever being evaluated.
